# خطة تحويل Ras Gharib Mobility إلى موقع ويب وتطبيق PWA حقيقي قابل للنشر الميداني

خطة تطوير شاملة تهدف إلى نقل منصة **رأس غارب موبيليتي** من مرحلة التطوير التجريبي إلى موقع ويب متكامل وتطبيق ويب تقدمي (PWA) فوري وسهل الاستخدام على هواتف أهالي وسائقي رأس غارب والبحر الأحمر، ليكون بديلاً موثوقاً وعصرياً لمجموعات فيسبوك ومحادثات واتساب غير المنظمة.

---

## مراجعة المستخدم والقرارات المحسومة (User Review & Critical Decisions)

> [!IMPORTANT]
> تم اعتماد التوصيات التشغيلية التلقائية لتسريع النشر الميداني وتسهيل تجربة الاستخدام:
> 1. **تثبيت PWA فوري على الموبايل**: توفير زر وواجهة تثبيت واضحة لإضافة التطبيق إلى الشاشة الرئيسية للهاتف (Android و iOS Safari) مع دعم العمل دون اتصال عبر Service Worker و Manifest.
> 2. **الحجز الفوري للمقاعد مع التحقق الحتمي**: يتم حجز المقعد مباشرة طالما المقاعد شاغرة مع منع التجاوز الحسابي التام ذرياً عبر الخادم، وتوفير زر اتصال فوري وزر محادثة واتساب بالسائق.
> 3. **التواصل المباشر**: إظهار رقم الهاتف المحمول ورابط مباشر لمحادثة واتساب بين السائق والراكب بمجرد تأكيد الحجز أو قبول عرض السعر.

- **القرار المؤكد 1**: الحفاظ الكامل على قاعدة بيانات Cloud Firestore الحقيقية الحالية (`ai-studio-rasgharibmobilit-958f3dc4-10bd-4d1a-ab61-5afe3589bf8d`) والمزامنة اللحظية عبر `onSnapshot`.
- **القرار المؤكد 2**: الحفاظ على تكامل خرائط Google Map Loader و Directions API القائم مع حساب مسافة الرحلة وزمن القيادة المتوقع.
- **القرار المؤكد 3**: عدم استخدام أي بيانات وهمية أو الاعتماد على التخزين المحلي فقط بين المستخدمين؛ كل حركة تُحفظ في Firestore المشترك.

## 1. نظرة عامة ومفهوم المنصة (Overview & Core Concept)

- **الهدف والوظيفة**: منصة نقل وسفر وشحن طرود خفيفة وسريعة مصممة خصيصاً لمدينة رأس غارب ومحافظة البحر الأحمر. تجمع بين الرحلات المجدولة مسبقاً (ميكروباصات وسيارات ملاكي للغردقة والقاهرة وقنا والسويس) وطلبات المشاوير الخاصة (بتقديم عروض أسعار تنافسية) وشحن الأمانات والطرود.
- **الجمهور المستهدف**: 
  - أهالي رأس غارب ومهندسو وعمال شركات البترول (رأس شقير والزعفرانة).
  - السائقون المحليون وأصحاب سيارات الأجرة والسفر المعتمدون.
  - إدارة المنصة في رأس غارب للمراقبة وفحص التراخيص وتسوية العمولات.
- **القيمة الأساسية**: إنهاء فوضى المنشورات على فيسبوك وتوفير وسيلة منظمة، سريعة، تحفظ الحقوق وتضمن معرفة الراكب لمواصفات السيارة والسائق وتقييمه قبل الركوب، مع الدفع النقدي المباشر عند الوصول.

## 2. تجربة المستخدم والتصميم البصري (User Experience & Visual Design)

- **التصميم المتجاوب والهندسة الموجهة للهواتف (Touch-First RTL)**:
  - واجهة عربية كاملة بنظام RTL مع خط تجوالي وعناوين بارزة.
  - شريط تنقل سفلي ثابت (Fixed Bottom Tab Bar) على الهواتف يضع الوظائف الحيوية (الرحلات، حجز مقعد، طلب مشوار، الطرود، حسابي) في متناول الإبهام (Natural Thumb Zone).
  - ارتفاع الأشرطة الثابتة أقل من 15% من الشاشة لترك 85% مساحة حرة للمحتوى والبطاقات.
  - أهداف لمس (Touch Targets) مطابقة لمعايير الاستخدام $\ge 44 \times 44\text{px}$.

- **الهوية البصرية والألوان**:
  - اللون الأساسي: أزرق بحري داكن (`#0B1F3A`) يرمز للمصداقية والرصانة الحكومية والتجارية.
  - اللون التفاعلي: أزرق كهربائي ساطع (`#146EF5`) لأزرار الإجراءات والروابط.
  - لون التأكيد والنجاح: زمردي (`#18B981`) لحالات القبول وتوفر المقاعد والتأكيد.
  - لون التنبيهات: عنبري (`#F59E0B`) لمراجعة التراخيص وقيد التدقيق.
  - الخلفية العامة: صخرية نقية ناعمة (`#F7F9FC`) لمنع إجهاد العين أثناء التصفح النهاري.

- **تدفقات المستخدم الأساسية (Core User Flows)**:
  1. **الراكب (حجز مقعد مجدول)**:
     - تصفح الرحلات المنشورة لليوم والغد ← اختيار الوجهة والموعد ← تحديد عدد المقاعد (1 أو 2 أو أكثر) ← تأكيد فوري يخصم المقعد من الخادم ذرياً ← ظهور كارت الحجز مع رقم هاتف السائق وزر محادثة واتساب بنص رسالة جاهز.
  2. **الراكب (طلب مشوار خاص / تاكسي)**:
     - إدخال نقطة الانطلاق والوصول (أو تحديدهما على خريطة Google التفاعلية) ← استلام زمن ومسافة الرحلة آلياً ← نشر الطلب في السيرفر ← استقبال عروض السائقين اللحظية مع وقت الوصول وسعر العرض ← قبول عرض واحد فقط وقفل البقية.
  3. **السائق (كابتن)**:
     - الاطلاع على طلبات الركاب المتاحة لحظياً عبر بث Firestore ← تقديم عرض سعر وزمن وصول ← استلام إشعار القبول ورقم هاتف الراكب للتواصل.
     - أو نشر رحلة سفر قادمة بموعد دقيق وسعر المقعد ليراها الركاب في جدول الرحلات.
  4. **إدارة المنصة (Admin)**:
     - فحص ومراجعة مستندات السائقين (الرقم القومي، رخصة القيادة، لوحة السيارة) واعتمادهم.
     - متابعة نسب العمولات وسجل العمليات المالية النقدية وتسويتها.
     - حل شكاوى وبلاغات الركاب.

## 3. القرارات التقنية والمعمارية (Key Product Decisions & Trade-Offs)

1. **دعم PWA عبر `vite-plugin-pwa`**:
   - استخدام `vite-plugin-pwa` لتوليد ملف `manifest.json` وأيقونات متوافقة وخدمة Service Worker مع خيارات التحديث التلقائي.
   - تضمين مكوّن `PWAInstallButton` في الهيدر والصفحة الرئيسية مع نافذة مساعدة مخصصة لمستخدمي iPhone (Safari Add to Home Screen).
2. **المعاملات الذرية لمنع التعارض الحسابي**:
   - حماية قبول العروض وحجز المقاعد باستخدام Firestore `runTransaction` لمنع حجز مقاعد أكثر من سعة السيارة ومنع قبول أكثر من عرض لنفس المشوار حتى في حالات الضغط المتزامن.
3. **تطبيق قواعد أمان صارمة في `firestore.rules`**:
   - السماح بالقراءة العامة لقائمة الرحلات والطلبات والعروض والسائقين حتى يتمكن الجميع من التصفح دون تسجيل دخول.
   - قصر التعديل الإداري وحالة اعتماد السائقين على حساب المشرف الرسمي (`gyoussef691@gmail.com`).
4. **تكامل خرائط Google Map Loader**:
   - التحقق من وجود `src/components/GoogleMapLoader.tsx` باستخدام `@googlemaps/js-api-loader` ومعالجة حالات غياب المفتاح بسلاسة عبر البديل التفاعلي الجغرافي.

## 5. خطة التنفيذ خطوة بخطوة (Execution Steps)

1. **التحقق من `GoogleMapLoader.tsx` وتحديثه**:
   - التأكد من استخدام `@googlemaps/js-api-loader` لتحميل الـ API بديناميكية عبر `VITE_GOOGLE_MAPS_API_KEY`، مع شاشة تحميل واضحة ومعالجة للأخطاء في حالة عدم توفر المفتاح.
2. **إعداد PWA الكامل (Progressive Web App)**:
   - إضافة `vite-plugin-pwa` إلى `package.json` و `vite.config.ts`.
   - إنشاء ملف Manifest مع هوية المنصة وألوانها ورابط الانطلاق.
   - إضافة مكوّن `PWAInstallPrompt` وهاتف/أيقونات التثبيت السريع على الشاشة الرئيسية.
3. **تفعيل أزرار الاتصال والواتساب الفوري**:
   - إضافة زر اتصال هاتفي وزر واتساب مباشر (`https://wa.me/20...`) لكل حجز أو عرض مقبول لتسهيل الاتفاق الفوري بين أهالي رأس غارب والسائقين.
4. **تحديث قواعد الأمان ومزامنة البيانات الحقيقية**:
   - مراجعة وتأكيد نشر `firestore.rules` لضمان عدم وجود أية أخطاء صلاحيات ومنع تجاوز المقاعد.
5. **الفحص والاختبار الشامل**:
   - تشغيل `tsc --noEmit` و `compile_applet`.
   - اختبار سيناريو إنشاء الطلب من حساب راكب وظهوره لدى السائق وقبول العرض بنجاح.
   - تقديم التقرير الفني النهائي مع رابط المشاركة العام وإرشادات التشغيل في رأس غارب.
